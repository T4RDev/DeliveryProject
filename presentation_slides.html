📁 ภาพรวมโครงสร้างระดับ Root (เปรียบเทียบ Front & Back)

ระบบแบ่งการทำงานออกเป็น 2 ส่วนหลัก เพื่อความเป็นอิสระและง่ายต่อการ Deploy

⚙️ Backend (`/Back`)

ระบบเซิร์ฟเวอร์ & อัลกอริทึม

  • เทคโนโลยี: Node.js, Express, TypeScript
  • พอร์ตเริ่มต้น: http://localhost:3000/api
  • หน้าที่หลัก:
    • ให้บริการ RESTful API ทั้งหมด
    • คำนวณแก้โจทย์เส้นทาง CVRP (Sweep + Nearest Neighbor)
    • จัดเก็บข้อมูลลูกค้า, ออเดอร์ และไรเดอร์ (In-Memory Database)
💻 Frontend (`/Front`)

หน้าจอแสดงผล & แผนที่โต้ตอบ

  • เทคโนโลยี: Angular 22, Tailwind CSS, Leaflet Map
  • พอร์ตเริ่มต้น: http://localhost:4200
  • หน้าที่หลัก:
    • Single Page Application (SPA) ทำงานรวดเร็ว
    • วาดเส้นทางไรเดอร์แยกสีลงบนแผนที่แบบ Real-time
    • แยก 3 หน้าจอ: แดชบอร์ดเจ้าของร้าน, จัดการออเดอร์, ใบงานไรเดอร์

⚙️ เจาะลึกโฟลเดอร์ Backend (`Back/src/`)

สถาปัตยกรรมแบบ MVC/Layered Service Architecture แยกหน้าที่กันอย่างเป็นระเบียบ

📂 controllers/ (ส่วนรับคำสั่ง API)

รับคำสั่ง HTTP Request จากเว็บ แล้วส่ง JSON กลับไป:

  • customerController.ts: ค้นหาเบอร์โทร, ค้นหาตามรัศมี
  • orderController.ts: รับออเดอร์, สุ่มสร้าง 24 ออเดอร์
  • dispatchController.ts: สั่งคำนวณเส้นทาง, จัดการใบงาน

📂 services/ (ส่วนคำนวณอัลกอริทึม)

ประกอบด้วยไฟล์ routingService.ts ซึ่งเป็นมันสมองของระบบ:

  • Sweep Algorithm: เรียงมุม Polar Angle รอบร้านตลาดน้อยเพื่อแบ่งโซนงาน ไม่ให้เส้นทางวิ่งตัดกัน
  • Capacity Limit: คุมโควต้าไรเดอร์ไม่เกิน 10 กล่อง/คน
  • Nearest Neighbor: เรียงลำดับจุดส่งที่ใกล้ที่สุดต่อเนื่องกัน

🗄️ Backend: ส่วนของฐานข้อมูล (`db/`) และ (`models/`)

การจัดเก็บข้อมูลและการสร้างโครงสร้างชนิดข้อมูล (Data Contract)

📂 db/ (การจัดเก็บข้อมูล)

  • database.ts:
    • จัดเก็บข้อมูลแบบ In-Memory Store ทำให้ทำงานได้รวดเร็วทันทีโดยไม่ต้องต่อฐานข้อมูลจริงภายนอก
    • ฟังก์ชัน calculateDistanceKm: ใช้สูตร Haversine คำนวณระยะห่างพิกัดจริงบนผิวโลก (กม.)
    • กำหนดพิกัดศูนย์กลาง: ร้านตลาดน้อย มมส. (16.2435, 103.2545)
  • schema.sql: ออกแบบ DDL ตาราง MySQL (customers, orders, riders, routes) สำหรับ Production

📂 models/ (โครงสร้าง Data Interface)

  • Customer.ts: ชื่อ, นามสกุล, เบอร์โทรศัพท์, ที่อยู่, พิกัด Lat/Lng
  • Order.ts: จำนวนกล่อง (ไม่เกิน 3 กล่อง/ออเดอร์), เวลาส่ง 12:30, สถานะ
  • Rider.ts: รหัสไรเดอร์, ชื่อ, ความจุสูงสุด (10 กล่อง), สีประจำตัว
  • Route.ts: ลำดับจุดจอดส่ง (Stops), สรุปเวลารวม, สรุประยะทาง

💻 เจาะลึกโครงสร้าง Frontend (`Front/src/`)

โครงสร้างเว็บทันสมัยด้วย Angular Standalone Components

📂 environments/

เก็บค่าการเชื่อมต่อ API:

  • environment.ts: สำหรับทดสอบในเครื่อง (localhost:3000)
  • environment.prod.ts: สำหรับใช้งานบนอินเทอร์เน็ต (เช่น Render Backend)

📂 app/services/

ตัวกลางเชื่อมต่อเครือข่าย:

  • api.service.ts: ส่ง HTTP Request (GET, POST, PUT, DELETE, PATCH) ไปยัง Backend อัตโนมัติ

📂 app/models/

โมเดลชนิดข้อมูลฝั่งหน้าเว็บ:

  • delivery.model.ts: กำหนด Interface ข้อมูลออเดอร์และเส้นทางให้ตรงกับ Backend

🔄 วงจรการทำงานร่วมกันระหว่าง Front และ Back (End-to-End Workflow)

ลำดับเหตุการณ์การส่งผ่านข้อมูลเมื่อใช้งานระบบจริง

  1. 1. บันทึกคำสั่งซื้อ: ผู้ใช้บันทึกออเดอร์ที่หน้าเว็บ Front (app.ts) ➔ ยิงผ่าน api.service.ts ➔ เข้า Back (orderController.ts) ➔ บันทึกลง database.ts
  2. 2. สั่งประมวลผลเส้นทาง: เจ้าของร้านกดปุ่ม "จัดเส้นทาง" ➔ ยิงไปที่ dispatchController.ts ➔ เรียกใช้งานอัลกอริทึมใน routingService.ts
  3. 3. อัลกอริทึมแบ่งงาน: ใช้ Sweep Algorithm แบ่งกลุ่มลูกค้าให้ไรเดอร์ (ไม่เกิน 10 กล่อง/คน) และจัดลำดับจุดส่งให้ทันก่อน 12:30 น.
  4. 4. วาดแผนที่: ส่งข้อมูล JSON แผนงานกลับมาที่หน้าเว็บ ➔ app.ts วาดเส้น Polyline บนแผนที่ Leaflet แยกสีตามไรเดอร์แต่ละคัน
  5. 5. ไรเดอร์ส่งมอบ: ไรเดอร์เปิดดูใบงานในโทรศัพท์ ➔ ส่งเสร็จกดส่งมอบ ➔ ระบบอัปเดตสถานะเป็น "Delivered" ทันที
